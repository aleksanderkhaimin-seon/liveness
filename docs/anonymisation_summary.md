**How to read the numbers.** Seed-to-seed spread at identical settings is 3–4 points on the test set and ~2 on production, so single-run differences inside that are noise. Three-epoch runs selected `best.keras` on `val_auc`; ten-epoch runs on `val_eer` (changed 2026-09-29, commit `69a47a0`). `ProdTest-0.3` is used both to select the checkpoint and to report the production number, so the ten-epoch figures are mildly optimistic; comparisons between rows remain fair.

**Two facts independent of anonymisation.** (a) Production EER is 12–15 % against 3 % on the in-distribution test set — the current training data does not transfer; production data in training is the remedy, and row 1 is what makes that possible. (b) On production the EER threshold is 10⁻⁴–10⁻², so at a 0.5 threshold 54–77 % of real replays are missed in every configuration; a production-derived threshold is needed whatever the training data.

**Open items for the next step.** DPO classification of row 1 (`docs/anonymisation_evidence.md`); empirical OCR / face-match audit of exported frames once detectors exist; a production corpus with bboxes for the real export; a selection/reporting split of `ProdTest-0.3` (or a second production set) for unbiased numbers; threshold calibration on production data. Visual examples of every row for any CSV: `python visualize_anonymization.py <csv> --out-dir <secure dir> --per-label 4` (output contains the originals — keep behind).
